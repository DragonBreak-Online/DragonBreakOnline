# The self-echo: what depends on a player getting their own movement back

PC load-test session, 2026-10-18. Task 1 of the 1,000-player work (`CAPACITY_PLAN.md` step 2). Everything below was
read with `git show origin/<branch>:<file>` on `origin/main` and on `origin/client-03103`, which is what players run.
Nothing here was read from this PC's working trees, which are 842 and 319 commits behind.

## The mechanism

`ActionListener::SendToNeighbours` (`skymp5-server/cpp/server_guest_lib/ActionListener.cpp`):

```cpp
const bool skipSender = !echoHostedToSender && idx != myActor->GetIdx();
for (auto listener : actor->GetActorListeners()) {
  auto targetuserId = partOne.serverState.UserByActor(listener);
  if (targetuserId == Networking::InvalidUserId || (skipSender && targetuserId == userId)) continue;
  partOne.GetSendTarget().Send(targetuserId, data, length, reliable);
}
```

`skipSender` can only be true for an actor that is **not** the sender's own (`idx != myActor->GetIdx()`), so a player's
own movement is always sent back to them. `OnUpdateMovement` validates first and relays second:

```cpp
if (!MovementValidation::Validate(...)) { return; }   // refused: no relay, no echo
if (isOwnActor) { SendToNeighbours(msg.idx, rawMsgData); }
```

So the echo is one message per movement per player: at 7.7 movements a second each, 7.7 echoes a second each.

## What consumes it on the client

| Consumer | Where | Live? |
|---|---|---|
| **Proximity voice** | `voiceService.pushPeers()`: `const me = forms[playerCharacterFormIdx]; const myMovement = me?.movement; if (!myMovement ...) return;` | Real dependency. Voice is built but switched off (`STATE.md`), so it is dormant, not dead |
| **`show-me`** draws your own character, offset 128 units | `formViewArray.updateAll`: `if (!form \|\| (playerCharacterFormIdx === i && !showMe)) { destroyForm(i); continue; }` | Off by default (`settings['skymp5-client']['show-me']`) |
| **The local-lag number** | `applyMovement`: `if (isMyClone === true) emit("newLocalLagValueCalculated", { lagUnitsNoZ })` -> `netInfoService.setLocalLagUnits` | Only with `show-me` on (it needs the own form rendered) **and** `show-net-info` on |
| **Client gamemode scripts** | `gamemodeUpdateService.setOwnerModel(myFormModel)` and `sweetTaffyEvalService`'s `_model` hand the own form to script code, which may read `_model.movement` | Whatever scripts do |

## What does not consume it

- **The anti-cheat snap-back does not.** `MovementValidation` builds a `TeleportMessage2` and sends it to the user
  directly (`MovementValidation.cpp`), so correcting a refused move is its own message, not the echo. A refused packet
  produces no echo at all, which is the point of validating before relaying.
- **The normal view does not.** The own form is destroyed in `updateAll` and in `syncFormView` unless `show-me`.
- **The clone view does not.** On `origin/client-03103`, `cloneFormViews.updateAll(model, false, true)` passes
  `showMe = false`, so the own form is destroyed there too, and it `continue`s before it can reach `playerCopies.spots`.
- `appearanceExtrasService` and `perfDiagService` both `continue` on the own index.

## Answer

**Yes, the server can stop echoing a player's own movement, and the client change is one line.**

The client already computes its own `Movement` every tick in order to send it (`sendInputsService.ts:159`,
`getMovement(owner, ...)`). Writing that same object into `worldModel.forms[playerCharacterFormIdx].movement`, with
`movementAt = Date.now()`, keeps voice, `show-me` and the gamemode `_model` working with no echo at all. That change
belongs with the client owner and should ship **before** the C++ change, so there is never a window where voice is on
and the echo is gone.

One thing cannot be preserved: the local-lag number measures the gap between the server's echoed position and the local
actor, so feeding it locally makes it read zero. It is gated behind two settings that are off, and the server already
measures the same thing better (`skymp_server_overall_ping_seconds` in `/metrics`). If anyone wants it kept, echo own
movement at 1 Hz instead of 7.7 Hz and the metric survives at a thirteenth of the cost.

## How much it is worth, honestly

The echo is 7.7 messages a second per player: about **1.2%** of all traffic at 100 players (770 of ~62,000), and about
**1.8%** of a client's inbound under the per-client budget `CAPACITY_PLAN.md` proposes for 1,000. It is cheap, safe and
tidy, but it is not the wall. Interest management (step 1) is worth two orders of magnitude more, and this should not
be allowed to consume any of the time that belongs to it.
